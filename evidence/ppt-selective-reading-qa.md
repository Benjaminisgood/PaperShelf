# 文献 PPT 与按需研读验收记录

日期：2026-10-18。作用目录：PaperShelf；没有修改 TAP。

## 实现范围

- PPT Master 6.7.2 完整源码作为未修改 submodule 保存，固定提交 `b113d23720260c411ee47b2b05a73615f954deeb`。适配层调用上游原生 DrawingML 导出、署名完整性检查、SVG 质量门禁及 PPTX 交付审计。同步脚本支持单独检查/更新此上游，保留本地适配代码。
- 研读面板分别生成文献 PPT、学习网页、研读 Markdown、全文 Markdown、字段与证据和文献 Agent；各自可以打开、重新生成及查看历史。未指定 outputs 的旧调用保留原有完整资料行为，不隐式增加 PPT。
- 章节、校订、摘要审核与续跑保留所选格式。续跑恢复原请求参数；更换模型连接配置后重新生成不再因旧缓存被直接拒绝。
- 左侧文库使用固定尺寸、明确前景色的图标，避免自动 Label 图标槽在窗口更新时消失。

## 已验证

- Python 全套 256 项测试成功，2 项因外部集成前置条件跳过；Swift 81 项测试通过。实际 PPT 导出测试覆盖可编辑文字、中文字体字段、讲稿、逐字证据、全块覆盖、失败/续跑缓存、原图字节保留与交付审计。
- 隔离 QA 文库中导入自建一页合成 PDF，点击“文献 PPT”生成 4 页可编辑 PPTX。该运行只发布 PPT 及共享来源产物，没有生成学习网页、字段数据或 Agent。
- 随后单独生成学习网页，原 PPT 仍可访问；再次生成 PPT 后菜单显示两个历史版本，旧运行与文件保留。
- 窗口由 1320 点宽缩放至 1710 点宽后，文库图标仍显示；研读面板保持可读。也执行了窗口拖动操作，但未捕获拖动过程的连续帧，不能据此证明所有系统状态下都不会复现。
- 直接渲染 SVG，并将真实 PPTX 转成 PDF 核对四页。验证用 bundled LibreOffice 默认字体配置遗漏 macOS AssetsV2/Font8 的中文字体；使用仅作用于验证进程的 fontconfig 后中文正常显示。
- 修正了中文替代字体下紧文本框导致的意外换行：仅扩大适配器自有单行框到预留内容区，保留文本、位置、字号和媒体；页脚避开页码。调整清单作为产物保留，之后再执行上游审计。
- 本机正式文库的受管 Python 环境已补齐新增导出依赖；没有改模型服务配置或文献原件。

## 验证边界

此次使用合成文档和离线真实导出；模型计划使用可控 Provider 验证输入、引用和缓存合同，没有调用用户的真实 AI 服务，也没有验证截图中的 HTTP 404 根因。引文匹配、测试通过和 PPTX 格式审计不等于科学结论通过验收。原文图表沿用现有提取范围，自动裁图仍需对照 PDF。未启用上游联网补图、AI 生图、动画或旁白。

生成文件、截图、详细测试日志和验证用字体配置留在忽略的 `.build/ppt-native-qa/` 与 `.build/`，不提交测试文库或原始文献。
